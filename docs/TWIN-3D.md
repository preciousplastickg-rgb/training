Формат `manifest.json`:

```json
{
  "version": 3,
  "twin": { "file": "twin.glb", "bfStart": 24.5, "bfGoal": 15 },
  "exercises": {
    "bench_press": {
      "file": "ex/bench_press.glb",
      "stills": ["ex/bench_press_start.webp", "ex/bench_press_end.webp"],
      "camera": { "position": [1.15, 1.7, 1.05], "target": [0.02, 0.66, -0.12] },
      "bounds": { "min": [-1.1, 0.0, -0.676], "max": [1.1, 1.341, 0.693] },
      "fit_points": [
        [0.74, 1.34, -0.25], [-1.1, 0.696, -0.125], [0.202, 0.011, 0.689], [0.019, 0.538, -0.588], ...  // до 64 точек
      ],
      "phases": [
        { "t0": 0.0, "t1": 2.0, "kind": "ecc" },
        { "t0": 2.0, "t1": 2.4, "kind": "hold" },
        { "t0": 2.4, "t1": 3.4, "kind": "con" },
        { "t0": 3.4, "t1": 4.0, "kind": "top" }
      ]
    }
  }
}
```

- `camera` — направление взгляда по умолчанию, при котором видны работающие мышцы: от `target` к `position`. Расстояние до фигуры задаёт не `camera`, а `fit_points` (ниже). Направление — читаемый ракурс (3/4, сбоку, сверху под углом), не вдоль оси снаряда; проверка — метрики видимости ниже.
- `bounds` — AABB тела двойника и **движущихся** снарядов этого файла по всем кадрам клипа: `{ "min": [x, y, z], "max": [x, y, z] }`, координаты glTF (Y вверх, пол на y = 0), метры, округлены наружу до 1 мм. Тело — `twin.glb` в позе клипа, без морфов. Движущиеся снаряды — то, что держит или толкает спортсмен: гантели, гриф, рукоять, каретка, рычаги тренажёра (у тренажёра с подушкой под колени — подушка с кареткой). Неподвижные опоры — скамья, стойка, рама тренажёра, сиденье, подушки — и удалённые части привода — стек грузов, тросы — в `bounds` не входят и на узком холсте могут уходить за край. У рычажного жима сидя (`machine_chest_press`) в кадр входят рукояти: рычаги поднимаются к оси на 0,7 м выше головы и вместе с осью и кулачком могут уходить за верхний край. С итерации 10 `bounds` оставлен для совместимости: кадр строится по `fit_points`, а если их нет — по `bounds`.
- `fit_points` — силуэт для кадра: не больше 64 точек `[x, y, z]` выпуклой оболочки тела и тех же движущихся снарядов по клипу (каждый второй кадр), координаты glTF, метры, 1 мм. Точки — вершины оболочки, выбранные так, что опорная функция набора в любом направлении отстаёт от полной оболочки не больше чем на 1 см (`exlib.hull_kernel`): проекция точек любой камерой даёт рамку силуэта, а не коробки. Порядок точек не важен. Все точки лежат внутри `bounds`.
- Кадрирование на любом холсте: камера смотрит по направлению из `camera`, перспектива с вертикальным углом 35°; расстояние и точка вращения подбираются так, чтобы перспективная проекция `fit_points` этой камерой занимала 85 % ограничивающей стороны холста (по высоте на вертикальном экране, по ширине на широком) и стояла по центру. Итерации (24): центр проекции сдвигается в ноль на глубине точки вращения, расстояние × max(высота, ширина) / 0,85. Без `fit_points` — восемь углов `bounds` со слабой перспективой (все на глубине центра, как в итерации 9). Эталон — `fitView()` в `viewer/main.js`, двойник для проверок в Blender — `exlib.fit_view`. Щипок масштабирует от найденного расстояния (0,5–1,7).
  Критерий приёмки (холст 390×619): силуэт тела с движущимися снарядами по всему клипу занимает не меньше 75 % ограничивающей стороны во всех упражнениях (по `fit_points` выходит 85 %); движущиеся части не обрезаются.
- Метрики ракурса в `exercise-anim/renders/check_<id>.json` — рендер плоскими цветами с камеры манифеста и кадрированием как в просмотрщике (холст 390×619, `fit_points` на 85 %), снаряды и опоры чёрные (`exlib.view_metrics`):
  - `primary_visible_share` — доля пикселей основных зон (`muscles.json → exercises.<id>.primary`) среди пикселей тела, **среднее по фазе `con`** (каждый второй кадр; у статики — по фазе `hold`). Порог 3 %; для упражнений с руками выше плеч (`db_shoulder_press`, `lateral_raise`) — 2 %: зона дельт при поднятых руках сжимается в полосу по верху плеча. Для справки — значения в начале, середине и конце фазы (`start`, `middle`, `end`) и минимум.
  - `equipment_occlusion` — доля пикселей тела, закрытых снарядами и опорами: 1 − (видимые пиксели тела) / (пиксели тела без снарядов), среднее по клипу (каждый 4-й кадр) — не больше 15 %; максимум и его кадр — для справки.
  - `head_visible` — доля пикселей головы (вершины с весом кости `head` ≥ 0,5), видимых при теле и снарядах, от пикселей головы, отрендеренной отдельно; среднее по клипу — не меньше 80 %; минимум — для справки.
- `phases` заменяют определение фазы по скорости грифа из прототипа: работает для любого упражнения, включая блоки и тренажёры.
- Упражнения без записи в манифесте показывают текущие подсказки и схему мышц (SPEC 6.6) без 3D.

### Скиннинг и морфы (итерация 13)

- **Скиннинг — DQS (двойные кватернионы, Preserve Volume в Blender).** Стандартный скиннинг three.js (LBS) при поднятых руках и в глубоких сгибах проваливает объём (плечо над головой — 0,74 объёма покоя). В шейдере тела чанки `skinbase`, `skinnormal`, `skinning` заменяются на DQS: на CPU каждый кадр из `bone.matrixWorld × boneInverse` считается пара кватернионов (поворот и сдвиг) на кость, uniform-массивы `uDqR[36]`, `uDqD[36]`; в вершинном шейдере 4 веса смешивают пары, знак каждой выравнивается по накопленной сумме (как `add_weighted_dq_dq` в Blender), результат нормируется; нормали поворачиваются тем же кватернионом. Эталон — `DQS_GLSL` и `updateDQ()` в `exercise-anim/viewer/main.js`, флаг `?skin=lbs` возвращает LBS для сравнения. Проверка: вершины против Blender (Preserve Volume) ≤ 1 мм в трёх позах (`renders/viewer_dqs_ref.json`; просмотрщик — 0,12 мм), FPS не ниже LBS (60 на тестовом стенде).
- **Морфы применяются до скиннинга** (как в Blender: ключи формы, потом Armature). Цели морфов `twin.glb` по порядку: `lean`, `muscle` — задаёт приложение по данным пользователя (раздел 4); `hand_open_L`, `hand_open_R` — раскрытые кисти; `fix_shoulder_up_L/R`, `fix_chest_press_L/R`, `fix_elbow_flex_L/R`, `fix_hip_flex_L/R` — корректирующие формы. Все разреженные (`tools/glbpost.py`).
- **Веса кистей и корректирующих морфов приходят из клипа** — канал `weights` glTF:
  - в `twin.glb` канал клипа `idle` нацелен на узел тела и содержит значения для всех его целей (у `lean`/`muscle` — 0): приложение берёт из него только анимируемые цели, `lean`/`muscle` не трогает; кисти в `idle` — 0,5;
  - в `ex/<id>.glb` тела нет: канал нацелен на узел-носитель `body_morphs` (сетка из одной точки, `extras.targetNames` — только анимируемые цели этого клипа). Приложение разбивает канал на дорожки по именам целей и вешает их на тело (`morphTracks()` в просмотрщике), узел-носитель удаляет из сцены;
  - при смене клипа все анимируемые цели сбрасываются в 0 (следующий клип ставит свои), на паузе первая поза клипа применяется сразу (`mixer.update(0)` после `play()`).
- **Корректирующие формы** (`exercise-anim/tools/correctives.py`): Delta Mush поверх DQS в зоне сустава и поправка объёма зоны (0,95–1,05 покоя), дельта переводится в позу покоя. Вес — по позе (`exlib.corrective_weights`, параметры в `exercise-anim/renders/correctives.json`): плечо и грудь — по направлению плеча в осях корпуса (1 в целевом направлении, до 0 за 80° и 50°), локоть и таз — по углу сустава (от 90° и 70° до 135° и 107°). Приложение веса не считает: они уже в клипе (каждый кадр).
- Упражнения без записи в манифесте показывают текущие подсказки и схему мышц (SPEC 6.6) без 3D.
- **В приложении (этап 5c).** Скиннинг в два шага, морфы — до обоих (`src/three/skinning.ts`, `src/three/engine.ts`):
  1. пропорции по обхватам (4.1) — линейно в позе связывания: `v₁ = Σ wⱼ · Pⱼ · v`, `Pᵢ = Bᵢ · Sᵢ · Bᵢ⁻¹` (`Bᵢ⁻¹` — `skeleton.boneInverses[i]`, `Sᵢ` — масштаб из `boneScale`; у костей без масштаба `Pᵢ` единичная). Стандартные чанки three.js `skinbase_vertex`, `skinnormal_vertex`, `skinning_vertex` остаются: подмена `skeleton.update` пишет в `boneMatrices` `matrixWorld тела × bindMatrix⁻¹ × Pᵢ` (штатный чанк умножает на `bindMatrixInverse`, обратную к `matrixWorld` тела, — выходит `Σ wⱼ · Pⱼ · v`);
  2. поза — двойными кватернионами после них (`dqsGlsl()`, `uDqR[36]`, `uDqD[36]`). `updateDQ()` — перед каждым `renderer.render` двойника (`draw()`): кадр «Сегодня», каждая из фигур «Старт · Сейчас · Цель», кадр на паузе и статичный кадр.

  Масштаб в матрицах костей, как до 5c, DQS отбросил бы (`decompose`) — шея, плечи, запястье и живот перестали бы меняться. В позе связывания шаг 2 единичный, поэтому пропорции те же, что при линейном скиннинге (unit-тест до 1e-6). `customProgramCacheKey` — с режимом скиннинга; `?skin=lbs` — прежний LBS, только в dev-сборке.
- Веса морфов из клипов — `src/three/morphTracks.ts`: цели по именам (`lean`/`muscle` — только через `morphTargetDictionary`, нет — ошибка загрузки), анимируемые — все остальные из словаря; дорожки `idle` и носителя `body_morphs` разбиваются по целям, носитель убирается из сцены и освобождается, клип без носителя теряет дорожки весов. Смена клипа — все анимируемые цели в 0, `play()`, `mixer.update(0)`; возврат в `idle` — кисти снова 0,5.
- Хуки для проверок: `__twin.morphs` (имя → вес), `__twin.skin`, `__twinVerts(t, neutral)` — вершины той же математикой на CPU (перенос `__viewerVerts`).

- Декодер Draco — в `public/draco/`, копирует `npm run sync-3d` (состав — ниже).

JS-фолбэк (`draco_decoder.js`) и энкодер не копируются; копии декодера из корня `libs/draco/`, на которые ссылается `DRACOLoader` через `import.meta.url`, в сборку не попадают (плагин `noBundledDraco` в `vite.config.ts`).

Самый крупный файл — `twin.glb`, 0,94 МБ; файлов больше 2 МиБ нет, предел Workbox по умолчанию. До 5c (этап 5b): 6,28 МБ, `public/3d/` 4,24 МБ.
- Одна сцена и один `WebGLRenderer` на всё приложение (`src/three/engine.ts`): канвас переносится между экранами. Двойник загружается один раз. Клипы упражнений и снаряды подгружаются и выгружаются по требованию.
- При закрытии sheet: остановить цикл, выгрузить снаряды и клип (`dispose`), тело оставить в памяти.

## 4. Тело по данным пользователя

Все формулы — чистые функции в `src/domain/twin.ts` с тестами.

- `bf` — процент жира по формуле ВМС США (SPEC 5.5) по последней талии и последней шее (могут быть из разных дней). Нет замеров — `bfStart` из манифеста.
- `lean = clamp((bfStart − bf) / (bfStart − bfGoal), 0, 1)`.
- `definition = clamp((bfStart − bf) / 12, 0.15, 0.9)` → `material.normalScale`.
- `muscle = clamp((сухая масса сейчас − сухая масса на старте) / 3 кг, 0, 1)`. Сухая масса — по SPEC 5.5, по 7-дневным средним.
- «Старт» — значения на `Settings.startDate`, «Цель» — `bf = bfGoal`, `muscle = 0`, пропорции — как «Сейчас», без поправки живота.
- История для ползунка «Прогресс → Тело» — по неделям, из средних за неделю. Неделя без замеров — значение интерполируется между соседними. Неделя без шеи — последняя шея до конца недели.

### 4.1 Пропорции по обхватам (9 ноября 2026, по просьбе пользователя)

Из 12 целей морфов `twin.glb` (раздел 2) обхваты передают только `lean` и `muscle`, поэтому шея, плечи, запястье и живот вне диапазона морфа меняют фигуру в движке: кожа вокруг костей части тела толще или тоньше. Пропорции остаются в движке и после этапа 5c. `TwinBody.shape` — множители к модели, 1 — модель как есть:

| Часть | Множитель | Кости (доля множителя) |
| --- | --- | --- |
| Шея | `шея / (0,226 × рост)`, 0,85–1,2 | `neck01`, `neck02` (1), `neck03` (0,6) |
| Плечи | `плечи / (0,666 × рост)`, 0,85–1,25 | `shoulder01` (1), `upperarm01` (0,6), `clavicle` (0,5), `spine01` (0,6); в покое ключица длиннее в `1 + 2 × (k − 1)` раз — плечевой сустав дальше от грудины |
| Запястье | `запястье / (0,1 × рост)`, 0,85–1,2 | `lowerarm02` (1), `lowerarm01`, `wrist` (0,6) |
| Живот | 1, пока `bf` между `bfGoal` и `bfStart` (талию передаёт `lean`); за пределами — `талия / талия при bf на пределе` (обратная формула ВМС), 0,85–1,3 | `spine04` (1), `spine03` (0,8), `spine05` (0,6), `spine02` (0,35) |

- Доли роста — средний мужчина (ANSUR II, округлено): при таких обхватах модель «как есть».
- Утолщение — поперёк кости (локальные x и z) и только в скиннинге: суставы и клипы не меняются, у каждой фигуры «Старт · Сейчас · Цель» свои пропорции. В «Как делать» ключица не удлиняется, чтобы руки оставались на снарядах; удлинение ключицы в покое (`joint.position`) — как было, её масштаб по длине входит в `Pᵢ`.
- Скиннинг в два шага (этап 5c, раздел 2 «Скиннинг и морфы»): сначала пропорции линейно в позе связывания (`Pᵢ = Bᵢ · Sᵢ · Bᵢ⁻¹` в `boneMatrices`, стандартные чанки), затем поза двойными кватернионами. До 5c масштаб стоял в матрицах костей (`matrixWorld × S × boneInverse`); DQS берёт из них только поворот и сдвиг, поэтому масштаб перенесён в шаг 1.
- Карточка «Замеры» в профиле показывает двойника: введённый замер сразу меняет фигуру.

## 6. Производительность и батарея

- «Как делать»: до 60 FPS, `setPixelRatio(min(devicePixelRatio, 2))`.
- «Сегодня»: не больше 30 FPS. Рендер только пока карточка на экране (`IntersectionObserver`) и вкладка видима (`visibilitychange`). Пока палец крутит фигуру и пока она докручивается по инерции — до 60 FPS, чтобы фигура шла за пальцем; затем снова ≤ 30.
- Первый кадр после открытия «Как делать» (ассеты в кэше): не дольше 1 с.
- Нет WebGL или 3D выключен в настройках → в «Как делать» манекен и подсказки (SPEC 6.6); потерян контекст или не загрузился клип → статичные кадры `_start.webp` / `_end.webp`. Включено «Уменьшение движения» в iOS → двойник в «Как делать» открывается на паузе, медленного вращения на «Сегодня» нет (пальцем крутится).

## 8. Экран и UI — детали
